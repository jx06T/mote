# 高中生 AI 作文訓練工具 — V1 開發規劃 (PRD)

> 版本：V1.0  
> 定位：個人開發、AI 輔助開發、Mobile-first、PWA  
> 技術方向：Vite + React + TypeScript + Cloudflare Workers + D1 + R2 + Google OAuth  
> 核心目標：建立「生活素材 -> 素材深化 -> 題目 -> 寫作／模擬考 -> 分析 -> 個人弱點 -> 下一次訓練」的完整閉環。

---

# 0. 產品定位與核心原則

本產品並非單純的「AI 作文產生器」或「AI 作文批改器」，而是一個**幫助高中生長期累積生活素材、練習思考與寫作，並追蹤自身寫作問題的作文訓練系統**。

### 核心原則
1. AI 優先「提問、引導、分析」，而不是代寫。
2. 學生自己的生活經驗是最重要的素材。
3. 電子作文訓練重視「寫作過程」，而不是只保存最後版本。
4. 模擬考必須模擬紙本考試：**手寫 -> 拍照 -> OCR -> 分析**。
5. AI 輔助產生的內容、修改、刪除，都必須留下可追蹤紀錄。
6. 所有個人資料都必須隔離，使用者只能存取自己的資料。
7. 第一版先完成核心閉環，不過度擴張功能。

# 1. 核心功能規格

## 1.1 隨手記錄 (Quick Notes)
- 目的：讓使用者在幾秒鐘內把生活中的片段留下來。
- 特性：
  - 不要求分類、標籤、標題、完整敘事。
  - 不強迫 AI 分析，可以只有一句話。
  - 支援手機快速輸入與自動聚焦。
  - 儲存後日後可以進入「深入探討」。

## 1.2 素材深入採集 (Material Deepening / Interview)
- 使用者選擇一則隨手記錄，點選「深入這件事」。
- AI 進入對話引導模式（單次一個核心問題，避免重複追問或過早總結）：
  - 了解事件背景、追問人物、時間、地點。
  - 追問具體畫面、對話、當時感受與後續發展。
  - 追問使用者後來的想法，找出可以延伸的主題。
- 對話完成後由 AI 生成結構化「素材卡」預覽，經使用者修改確認後寫入素材庫。

## 1.3 素材庫 (Material Library)
- 素材卡資料欄位：
  - 標題、故事、人物、時間、地點、具體畫面、對話、感受、後來的想法、可延伸主題、標籤、建立時間、最後修改時間。
- 支援多標籤分類、檢索與編輯，避免單一限制。

## 1.4 素材反向搜尋 (Material Reverse Search)
- 核心目標：針對特定作文題目，反查「我的人生中有什麼故事可以寫」。
- 流程：
  1. 輸入或拍攝題目。
  2. 題目解析（關鍵字、主題萃取）。
  3. 搜尋個人素材庫並進行相關性排序。
  4. 顯示推薦理由（分為「很適合」、「可以考慮」、「關聯較弱」）。
  5. 選擇素材直接代入寫作流程。

## 1.5 題目庫 (Prompt Library)
- 題目來源：拍照、上傳圖片、手動輸入。
- 題目資料：原始圖片、OCR 文字、人工修正後文字、題型、建立時間、使用紀錄。
- 原始題目圖片永遠在 R2 中保存，OCR 結果必須支援人工校正。

## 1.6 電子作文訓練、編輯器與文章庫 (Essay Editor, Library & Operation History)
- 編輯器架構：基於 Tiptap / ProseMirror，模擬實際寫作思考過程。
- 文章庫與歷史紀錄管理 (Essay Library & History)：
  - 完整保存每篇作文草稿、標題、關聯題目、即時字數統計、建立時間、更新時間與狀態（草稿 draft、已交卷 submitted、已評析 analyzed）。
  - 提供獨立文章庫檢視頁面（`/essays`）與編輯器內快速切換抽屜（`EssayListDrawer`），方便學生隨時回顧歷史文章、切換草稿或新建空白作文。
  - 支援關鍵字搜尋、狀態篩選、文章刪除管理與一鍵繼續撰寫。
  - 訪客模式於本地 LocalStorage 即時儲存，登入後無縫同步至 Cloudflare D1 雲端資料庫。
- 編輯限制與歷史追蹤：
  - 即時連續輸入允許直接退格修改。
  - 歷史長段文字刪除不直接永久清空，而是記錄為 `DELETE operation`。
  - 所有關鍵操作記錄至 `essay_operations`：`INSERT`, `DELETE`, `REPLACE`, `AI_SUGGESTION`, `AI_ACCEPT`。
- AI 寫作輔助（浮動工具列）：
  - 功能：比喻、仿寫、擴寫、精簡、增加情緒、增加畫面。
  - 流程：選取句子 -> AI 產生建議 -> 顯示原句與建議 -> 使用者決定「採用」或「不用」-> 採用時記錄 `AI_ACCEPT` 並寫入新版本。嚴禁 AI 直接無提示覆蓋原文。

## 1.7 難字與字詞功能 (Hard Characters & Vocabulary)
- 使用者可在編輯器中標記難字（如易錯字、生難字）。
- 建立個人難字資料庫（字形、來源作文、熟悉度、測驗紀錄）。
- 提供注音測驗、看詞填字、看句填字複習。

## 1.8 作文分析 (Essay Analysis)
- 交卷後進行結構化面向分析：
  - 切題、立意、素材、結構、描寫、語言、情感、結尾、具體問題、下一次訓練建議。
- 重點在於「具體哪裡做得好、哪裡有問題、下一次該練什麼」，而非單一 AI 分數。

## 1.9 紙本模擬考 (Paper Mock Exam)
- 核心原則：模擬考模式嚴禁使用電子作文編輯器與任何 AI 輔助工具。
- 流程：選擇題目 -> 設定計時 -> 倒數計時並紙本手寫 -> 交卷 -> 拍照（多頁、旋轉、裁切、順序調整）-> 上傳 R2 -> OCR 文字辨識 -> 人工確認 OCR -> AI 作文分析 -> 更新個人弱點。

## 1.10 個人弱點資料庫 (Personal Weakness)
- 弱點維度：立意、切題、結構、描寫、語言、議論、結尾、轉折、素材、字詞。
- 累積多篇作文後分析使用者寫作特徵（擅長項目、需加強項目、長期演進趨勢）。

# 2. 系統架構與安全原則

### 2.1 身份驗證 (Google OAuth 唯一)
- 唯一登入方式為 Google Account OAuth，禁止其他第三方登入或 Email/密碼。
- 後端 Worker 驗證 Google Token 並簽發 Session。

### 2.2 權限與資料隔離
- 任何 API 存取與 R2 檔案路徑均需通過身份驗證與資源擁有權檢查 (`user_id === currentUser.id`)。
- 前端 React 絕對不直接呼叫外部 AI Provider，所有 AI 請求均由 Cloudflare Worker 後端中繼並控管 API Key、速率與 Token 成本。

### 2.3 離線與 PWA 原則
- Mobile-first 設計（主要支援 375x812, 390x844, 430x932 等視窗）。
- App Shell 離線可開，電子作文草稿具備本機備份機制。
- AI 與 OCR 功能在離線時明確提示需連網，不假裝可用。
